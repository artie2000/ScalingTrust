# ProVerif in Lean

[ProVerif](https://bblanche.gitlabpages.inria.fr/proverif/) verifies
cryptographic protocols in the symbolic model: a protocol is a process in a
variant of the applied pi calculus, the attacker is Dolev–Yao, and a query asks
for secrecy or for a correspondence between events. This folder embeds that
calculus in Lean so that ProVerif models, among them the ones Noise Explorer
generates for the Noise handshakes, can be reasoned about in Lean. It has three
parts, each a subfolder with its own README.

| Subfolder | What it is |
| --- | --- |
| `TraceSemantics/` | A shallow semantics of the calculus: a process is the set of traces it can perform, the attacker is the set of traces the Dolev–Yao rules allow, and secrecy and correspondence are properties of the attacks on a process. Translated models are written in it and proofs about them are proofs in it; `DH.lean` and `Examples.lean` there are its tests, the survey's running example translated by hand. |
| `Specification/` | ProVerif itself, deeply: the syntax and operational semantics of its calculus and the meaning of its queries, as the write-up restates them from the survey; the denotation of a process as a set of traces; and the proofs that the two semantics agree on secrecy and correspondence, the theorems of the write-up. Nothing is formalised here yet. |
| `Translation/` | A translator from a fragment of ProVerif's input language to Lean source over `TraceSemantics/`, following the recipe its README records: Lean's parser reads the model and Lean's pretty printer writes the translation. `Examples/` there holds two models and their translations, which the build checks. |
| `Writeup/` | `Semantics.tex`, the mathematical account of the trace semantics, of the denotation of the calculus in it, and of the correspondence with the operational semantics. Its PDF is tracked; rebuild it with `pdflatex` after editing the source. |
| `Reference/` | The survey, the manual, the papers the design draws on and two models generated by Noise Explorer; its README says what each file is. |

The subfolders are not independent of one another, unlike the folders under
`ScalingTrust/`. `Specification/` imports `TraceSemantics/` and `Translation/`
emits code against it; `TraceSemantics/` depends on neither, and the other two
not on each other: the translator does not go through the syntax of
`Specification/`, since the point of the shallow embedding is that a translated
model is ordinary Lean.

## Building

The folder depends on Mathlib, pinned in the root `lakefile.toml`; fetch it with
`lake exe cache get`. `ScalingTrust/ProVerif.lean` imports every module of the
folder and is part of the default target, so `lake build` builds it and CI
checks it;

```sh
lake build ScalingTrust.ProVerif
```

builds the folder alone.
