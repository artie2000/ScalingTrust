# The process calculus behind ProVerif, as trace sets

A trace-based semantics for the calculus of Blanchet's survey *Modeling and
Verifying Security Protocols with the Applied Pi Calculus and ProVerif* (FnTPS
2016, Fig. 2.4), kept as simple as possible while still able to state ProVerif's
queries. It is meant as the target of a translation from ProVerif models. The
embedding is shallow: a process is the set of traces it can perform, what a
process computes between actions is ordinary Lean code, and the attacker is not
a program but the set of traces the Dolev–Yao rules allow.

This folder depends on Mathlib (pinned in the root `lakefile.toml`; fetch it
with `lake exe cache get`). It is not part of the default target yet; build it
with

```sh
lake build ScalingTrust.ProVerif.Examples
```

## Translating a ProVerif model

A model is translated piece by piece, types erased as in the survey's semantics.
`ProVerif.DH` and `ProVerif.Examples` follow this recipe for the survey's running
example.

1. **Free names** (`free a`) become nullary constructors, `DH.Fun.const a` over a
   type of the model's free names; `Msg.name n` is reserved for the nonces that
   `new` creates.
2. **Constructors** (`fun`, `const`) become the symbols of a signature `F : Sig`.
3. **Equations** (`equation`) become a `Theory F`: the equations `E`, and the
   symbols declared *free*, every symbol that is not at the root of a side of an
   equation (`Theory.heads`, proved by `rfl`). `Msg T`, terms modulo `E`, is the
   message type, and Lean's `=` on it is the survey's `=_E`.
4. **Destructors** (`reduc`) become Lean functions to `Option (Msg T)`, `none`
   being `fail`: a `match` on `Msg.view` of the arguments, with one branch per
   rewrite rule in order and a final `none`. A nested pattern over a free symbol
   is a nested match; a repeated variable is an equality test. A destructor
   whose rules have no may-fail variable is written on messages and lifted by
   `strict`; one with may-fail variables takes `Option (Msg T)` arguments
   directly.
5. **Public and private** declarations become a `Pub T` instance: `pubFun` the
   public constructors, including the public free names, and `dtors` the public
   destructors.
6. **The process** becomes a `do` block in `Cont (Proc (Msg T))`, closed with
   `Proc.run`: `out` is `Proc.send`, `in` is `Proc.recv`, `new` is `Proc.fresh`,
   `event` is `Proc.emit`, `P | Q` is `if ← Proc.fork then P else Q`, `!P` is
   `Proc.repl` followed by `P`, and `0` is `Proc.stop` or the end of the block.
   `let x = D in P else Q` is a Lean `match` on the destructor's result, and
   `if M = N then P else Q` a Lean `if` on the equation of messages. The process
   never uses `Msg.name` or `say`.
7. **Queries**: `query attacker(M)` is `Secret`, for `M` without nonces;
   `query F ==> H` is `Corr`, with `F` and `H` instantiated by valuations of the
   query's variables.

## The semantics

**Actions.** `Act M` has `out c m`, `inp c m`, `new n`, `event e` and `say m`,
where the name created by `new n` is `Names.nonce n`. `say m` is the attacker's
declaration that it knows `m`; honest processes never use it. Processes and the
attacker are written for any message type `M` with `Names M` and `Attacker M`;
a translated model uses `Msg T` with the instances of `ProVerif.Query`.

**Processes.** `Proc M` is `Set (List (Act M))`; every process built here is
prefix-closed, so a trace is an execution so far and a process that blocks
simply has no longer traces. `Proc.out`, `Proc.inp`, `Proc.new` and
`Proc.event` prepend an action and `Proc.nil` is `0`; `Proc.new` creates a
name that the rest of the process does not create again. The `do`-notation of
step 6 is built from these in the continuation monad.

**Parallel composition.** Two stages. First the component traces
`f : ι → List (Act M)` are interleaved into a tagged trace
`s : List (ι × Act M)`: `Interleaves f s` says that each component reads its
own trace back off `s` by projection, so interleaving needs no rules at all.
Then `comms s` is the set of traces obtained by letting an output immediately
followed by a matching input of a *different* component meet in a
communication, the survey's rule (Red I/O), which leaves nothing in the trace.
`Proc.merge` combines the two and keeps only the traces whose created names are
distinct, so that different components never create the same name; `Proc.par`
is the merge over `Fin 2` and `Proc.bang` the merge over `ℕ` (a trace is
finite, so only finitely many copies act). `Proc.bang_eq`, `!P = P | !P`, is
(Red Repl).

**Completed communications.** `out` and `inp` are offers. A trace with no
unfinished action (`Act.Unfinished`) is one in which every offer met a partner,
and then `out_of_inp_comms` says that whatever one component received, another
component sent.

**Messages.** `Msg.view` shows a message's head symbol and arguments when the
symbol is free and nothing otherwise, and `Theory.view_congr` proves it
invariant under `E`, so a destructor matching on the view is a function on
messages. This deviates from the survey, which matches rewrite rules modulo `E`;
the head of `Term.lean` says why the two agree for every destructor that can be
written. A predicate on messages has to respect `E`; `Msg.lift` produces one
from any structure that satisfies the equations, and that is how the closed
sets of secrecy proofs are defined.

**The attacker.** For `Msg T` the attacker is the Dolev–Yao attacker of the
algebra. What it can deduce from a set of messages, `derive`, is the least
superset closed under the public operations of `Pub T` (`Attacker.ofOps`),
ProVerif's `attacker` predicate (survey §3.2.2); an argument may be `fail`
(`none`), which the attacker can always write. `Enemy K` is the most general
intruder as a process: knowing `K`, it may receive on any channel it can derive
(learning the message), send anything it can derive on any channel it can
derive, create names, and say anything it can derive.

**Attacks and queries.** `Attacks P` is the process of traces of `P | Enemy ∅`
in which no action is unfinished: ProVerif's `P | Q` for every adversary `Q` at
once. Queries are properties of the actions of an attack. `Secret P s` says
that in no attack does the attacker say `s`. `Corr P Hyp Concl` says that each
instance of `F` is one under a valuation whose instance of `H` occurs no later;
`F` is an event, or `attacker(M)` as `say M`. `secret_of_closed` is the
closed-set method for secrecy: a `derive`-closed set that contains every nonce
and every message the protocol offers bounds everything the attacker can ever
say, provided the protocol itself never says anything. `Examples.hashed_secret`
uses it; `Examples.leak_attack` exhibits an attack instead.

## Design decisions

* **Synchronous.** Communication is a rendezvous, as in the survey, not
  ProVerif's Horn-clause approximation in which outputs are persistent facts.
  A single sequential process cannot communicate with itself: the two partners
  must be distinct components, which is why communication is defined on the
  tagged interleaving, where the components are still known, rather than read
  off adjacent actions of an untagged trace.
* **A communication leaves no action.** A query can observe the events of an attack
  and what the attacker says, and nothing else; what was communicated is
  recoverable from the component traces when a proof needs it.
* **The attacker speaks.** An attack does not record what the attacker learnt, so
  its knowledge is made visible by `say`, as with the intruder of Schneider's
  CSP approach: at any time it may say anything it can derive. This is what
  lets `attacker(M)` appear in a correspondence like an event.
* **Channels are uniform.** Nothing marks a channel public or private: a
  private channel is a term the attacker cannot derive, on which `Enemy` makes
  no offers.
* **Free names are constants.** The survey keeps free names apart from
  function symbols, making them public or private through an environment
  `(N_pub, N_priv)`. Here a free name is a nullary constructor, as the ProVerif
  manual treats it (§6.7.3: a free name, a constant and a top-level bound name
  "all declare a constant"), and only the names `new` creates are names. So
  `Pub` alone says what is public, and the attacker starts from `∅`, the public
  free names being derivable from nothing. The survey's Def. 3.2, whose public
  channel must be a name, is the one definition this changes; see `Secret`.
* **Freshness by index.** Rather than "the new name occurs nowhere", the
  indices of all the `new`s in a trace are distinct: `Proc.new` refuses to
  create a name the rest of the process creates again, `Proc.merge` refuses
  traces in which two components created the same name, and `Enemy.new` does
  as `Proc.new`. This is Paulson's `Nonce N ∉ used evs` pushed into the
  constructors, and the applied pi convention that bound names are pairwise
  distinct.

## Not modelled

Tables (`insert` and `get`; the ProVerif manual, §6.7.3, encodes them with
private channels), phases (attacks are ordered, so ordering constraints can be
stated directly), injective correspondences and the secrecy of bound names
(`query secret x`). The Noise Explorer models in `Reference/` use tables and
phases, so they mark what remains.

  deduction relation, in PVS.

  `do`-notation.
